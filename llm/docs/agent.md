# Agent 是什么

Agent（智能体）是“能够基于目标自主决策并执行动作”的 LLM 应用形态。
和普通 Chat 不同，Agent 不只是一次性生成答案，而是会在“思考 -> 选择动作 -> 执行工具 -> 观察结果 -> 再决策”的循环中完成任务。

简化理解：

- Chat：只回答
- Workflow：按固定流程执行
- Agent：在流程中可动态决策和调用工具

---

## Agent 的基本构成

一个可用的 Agent 通常包含以下组件：

### 1) Model（大模型）

- 负责理解指令、生成计划、选择下一步动作
- 常见是支持 tool calling/function calling 的对话模型

### 2) Prompt / Instructions（系统提示词）

- 定义角色、目标、边界和输出规范
- 约束何时调用工具、何时直接回答

### 3) Tools（工具）

- Agent 与外部世界交互的手段
- 例如：搜索、数据库查询、代码执行、API 调用、RAG 检索

### 4) Memory（记忆）

- 保存对话历史、用户偏好和关键事实
- 常见策略：窗口记忆、摘要记忆、向量检索记忆、实体记忆

### 5) Planner / Policy（规划与策略）

- 决定“下一步做什么”
- 可能是显式规划（先列计划）或隐式规划（边做边推理）

### 6) Executor（执行器）

- 按模型决策真正调用工具
- 处理参数校验、重试、错误回退

### 7) Observation & Feedback（观察与反馈）

- 把工具返回结果回填给模型
- 模型据此继续推理，直到满足停止条件

### 8) Guardrails（安全护栏）

- 权限控制、敏感操作确认、输入输出过滤
- 防止越权调用、提示注入和危险操作

---

## 常见 Agent 类型

### 按任务形态

- **Task Agent**：完成单个任务（如“查天气并汇总”）
- **Workflow Agent**：在多步骤业务流中动态决策
- **Multi-Agent**：多个角色协作（计划者、执行者、审查者）

### 按工具能力

- **纯对话 Agent**：无外部工具，只靠模型知识
- **Tool-Using Agent**：可调用搜索/计算/API 等工具
- **RAG Agent**：结合知识库检索进行回答
- **Code Agent**：能读写代码、运行命令和调试

### 按记忆机制

- **无记忆 Agent**：每轮独立处理
- **短时记忆 Agent**：仅保留最近几轮上下文
- **长时记忆 Agent**：摘要或向量库存储长期信息
- **结构化记忆 Agent**：实体清单/知识图谱记忆

---

## 什么时候该用 Agent

适合用 Agent 的场景：

- 任务步骤不固定，需要动态决策
- 需要跨系统调用多个工具
- 需要根据工具结果反复迭代

不建议一开始就用 Agent 的场景：

- 任务流程非常固定（优先普通 Workflow）
- 只需单轮问答（优先简单 RAG/Prompt）

---

## 一句话总结

Agent = `LLM + Prompt + Tools + Memory + Policy + Guardrails`。
它的核心价值是：在复杂任务中“能自主决策并可执行”，而不是只生成文字答案。

## 如何实现 Agent 的记忆和工具使用

### 1) 记忆实现的推荐分层

实际项目里建议把记忆拆成三层，而不是只放一种 memory：

- **短时层（Working Memory）**：最近 N 轮消息，保证当前对话连续性。
- **长时层（Long-term Memory）**：摘要或向量检索，保存跨轮关键事实。
- **结构化层（Fact Memory）**：实体/KG/用户画像，保存稳定信息。

常见组合：

- `窗口记忆 + 摘要记忆`：控制长度 + 保留主线。
- `窗口记忆 + 向量记忆`：保留上下文 + 语义召回细节。
- `窗口记忆 + 实体记忆`：聊天体验稳定记住“人/偏好/地点”。

### 2) 工具使用的实现模式

推荐把工具抽象成统一接口（名称、描述、参数 schema、执行函数）：

- **工具描述（description）**：告诉模型何时该调用。
- **输入约束（schema）**：避免参数错误。
- **执行器（executor）**：负责权限、重试、超时、日志。

建议工作流：

1. 模型判断是否需要工具；
2. 选择工具并组装参数；
3. 执行工具并拿到 observation；
4. 把 observation 回填给模型；
5. 判断是否继续循环或结束回答。

### 3) 记忆与工具协同

高质量 Agent 不是“会调工具”就够了，还要让记忆参与决策：

- 调工具前：先查记忆，避免重复查询；
- 调工具后：把高价值结果写回记忆（摘要或向量库）；
- 回答时：同时使用“检索记忆 + 新工具结果”。

简化原则：

- 把“工具结果入库”当成标准步骤；
- 只写入高价值信息，避免记忆污染；
- 给每条记忆打 metadata（时间、来源、置信度）。

## 开发 Agent 的最佳实践和安全提示

### 最佳实践

- **先做最小闭环**：先 1 个模型 + 1-2 个工具跑通，再扩展。
- **显式状态管理**：把会话状态、工具结果、记忆写入分开存储。
- **限制循环步数**：设置 `max_iterations`，防止死循环。
- **工具优先级设计**：定义“何时禁止工具调用”与“何时必须调用”。
- **失败可恢复**：工具失败时要有 fallback（重试、降级回答、请求澄清）。
- **可观测性先行**：保留每一步输入、输出、耗时、错误。

### 安全提示

- **最小权限原则**：工具只开放必要能力，不给全盘系统权限。
- **高风险操作二次确认**：删除、转账、发邮件等必须人工确认。
- **提示注入防护**：外部文本（网页、PDF、用户输入）默认不可信。
- **输出安全过滤**：对敏感信息、隐私、违规内容做后处理检测。
- **网络与文件隔离**：生产环境使用沙箱和白名单访问。
- **审计与追踪**：关键操作记录 trace id、调用链和参数快照。

## LangSmith 和 LCEL 是什么？如何使用

### 1) LCEL 是什么

LCEL（LangChain Expression Language）是新版 LangChain 的链式组合方式。
核心思想是：把 Prompt、Model、Parser、Retriever、Memory 都当成 Runnable 组件，用 `|` 组合成可观测、可复用的流水线。

典型形态：

- `prompt | llm | parser`
- `retriever -> docs -> combine_chain`
- `RunnableWithMessageHistory(chain, ...)`

LCEL 的优势：

- 结构清晰，组合灵活；
- 易插拔（可替换模型、解析器、检索器）；
- 更适合新版生态和后续升级。

### 2) LangSmith 是什么

LangSmith 是 LangChain 生态的可观测与评测平台，主要解决：

- **Trace 追踪**：查看每一步调用链路；
- **调试分析**：定位提示词、工具、检索、记忆问题；
- **评测与对比**：对比不同 prompt/model/agent 配置效果；
- **线上监控**：观察失败率、延迟、成本与质量趋势。

### 3) 如何使用（落地步骤）

1. 本地先用 LCEL 组装链路（确保逻辑清晰可拆）。
2. 接入 LangSmith trace（开发阶段先观察完整调用链）。
3. 给关键节点打标签：tool calls、retrieval hits、memory updates。
4. 建评测集（常见用户问题 + 期望输出标准）。
5. 对不同版本 prompt / 工具策略做 A/B 对比。
6. 把“高失败场景”回流到测试集，持续迭代。

### 4) 一条实战建议

把 LCEL 当“构建层”，把 LangSmith 当“观测层”：
前者保证你能快速搭系统，后者保证你能持续把系统做稳定、做可控。

## 补充：DeepMind 的 AutoRT 是什么

AutoRT（Automatic Robot Transformer，常被称为“自动化机器人数据生成与训练框架”）是 DeepMind 在机器人智能体方向提出的一套方法论。
它的核心目标不是只做一个“会对话的 Agent”，而是构建一个能够在真实环境中持续学习的机器人闭环系统。

### 1) AutoRT 的核心思路

AutoRT 重点解决“机器人数据不够、泛化不足、标注昂贵”这几个问题，核心做法是：

- 用视觉语言模型（VLM）理解场景和可执行动作；
- 让机器人在真实环境中自主尝试任务；
- 自动收集交互轨迹并筛选高价值样本；
- 将新数据回流训练，不断提升策略表现。

可以把它理解成“机器人版的 Agent 数据飞轮”。

### 2) 与普通 LLM Agent 的区别

- 普通软件 Agent：主要在文本/工具/API 世界里行动。
- AutoRT：在物理世界中行动（感知、规划、控制、执行）。

这意味着 AutoRT 必须额外处理：

- 机械臂控制约束与碰撞风险；
- 视觉感知误差和环境不确定性；
- 安全边界（人机共处场景尤其重要）。

### 3) 典型闭环（简化）

1. 任务输入（自然语言或预定义目标）
2. 场景感知（摄像头 + VLM 解析）
3. 动作生成与执行（pick/place/open 等）
4. 结果评估（成功/失败/异常）
5. 数据筛选与回流训练（持续迭代）

### 4) 对 Agent 工程的启发

即使你不做机器人，AutoRT 的方法也很有借鉴价值：

- **数据飞轮优先**：系统要能自动产生“下一轮训练数据”。
- **评估内建**：每次执行都要有成功标准和质量标签。
- **安全先行**：高风险动作必须分级授权与确认。
- **持续学习架构**：在线执行与离线训练要形成闭环。

### 5) 局限与挑战

- 真实世界试错成本高，硬件和运维门槛高；
- 场景迁移难，跨环境泛化仍是难点；
- 安全、伦理与责任归属要求更严格。

一句话理解：
AutoRT 代表的是“从软件 Agent 走向现实世界智能体”的工程路线，重点在于**自动数据采集 + 持续学习闭环 + 安全约束**。
